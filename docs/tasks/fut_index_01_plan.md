# FUT-INDEX-01: supplied STAR index decision brief

The [main matrix](backlog_matrix.md#platform-operation-and-portability) owns the
Open outcome and acceptance. The accepted outcome is an explicitly supplied,
content-bound STAR index reused without generating, repairing, merging or mutating
it. Existing processing-Run reuse and standalone validation do not supply this
feature. Field names, custody, schemas, graph mode and CLI below remain proposals.

## Historical provenance and STAR policy

The existing seven Step 00a checks cover required names, recorded FASTA/GTF paths,
ordered contig names/lengths and three settings. They do not bind historical source
hashes or exact producer identity. A failed row need not cause standalone process
failure; admission must read every required result. Generated Run Task admission
already applies semantic all-pass. Preserve those seven IDs and generated meaning.

STAR `versionGenome` is a compatibility floor (`2.7.4a` for release `2.7.11b`),
not the producer release. Runtime version/binary admission is separate from the
external producer. Native metadata/override text and optional `Log.out` omit
parts of an effective recipe and cannot authenticate code or a completed build.
Examples include suffix-length and GTF gene-name/type defaults; metadata is written
before all large members. Current reference-provenance inventory can allow unknown
hashes and one index row, so it is not supplied-index admission authority.

Candidate routes, neither yet approved:

| Route | Required basis and limit |
| --- | --- |
| Retained EMRYS Run | Re-admit original source/Task/success/output evidence and present complete bytes from the producer Run. A copied JSON marker or detached directory does not inherit authority; executable observation is not atomic proof against a concurrent binary writer. |
| Foreign producer | A preaccepted issuer/custody mechanism attests producer-time source/code snapshots, closed effective recipe, observed zero exit and post-success full inventory. Current bytes/native metadata must agree. An issuer name, self-signed record or digest cannot authorize its own trust root. The claim remains attested origin under an explicit stability assumption. |
| Native metadata or post hoc manifest only | May establish present compatibility but cannot establish the historical FASTA/GTF bytes; refuse historical-source admission rather than silently weakening the outcome. |

The proposed narrow foreign recipe is one STAR 2.7.11b FASTA/GTF build, no parameter
files, added junction/source or transform inputs, and only the current worker's
nine options: `runThreadN`, `runMode`, `limitGenomeGenerateRAM`, `genomeDir`,
`genomeFastaFiles`, `sjdbGTFfile`, `sjdbOverhang`, `genomeSAindexNbases`,
`genomeChrBinNbits`. Bind ordered arguments, working directory, thread/memory
controls and all effective defaults to the attested source/build **and binary**.
This includes `genomeSAsparseD=1`, `genomeSuffixLengthMax=-1` and GTF tag defaults.
Broader recipes require separate characterization; this sketch is not a schema.

Before STAR reads, retain real source paths, sizes/digests and held immutable
source/executable snapshots or trusted writer exclusion, plus an isolated fresh
output. Retain observed launch/success and seal every post-success member outside
the index directory under accepted custody. Post-exit matching hashes corroborate
stability but cannot replace writer control. Original paths versus relocated
content require a separate policy, not reinterpretation of generated path rows.

## Complete directory, graph and identity

The protected minimum is fifteen nonempty regular members, while STAR consumes
the entire directory. Bind ordered names, sizes and hashes for every member,
including hidden/extras, with before/after identity and membership checks. Decide
symlinked ancestors, nested/nonregular entries, empty extras and writable hardlinks.
The old generated producer allows an empty extra that Stage 01 input admission
rejects; the narrow supplied proposal rejects it early without changing generated
behavior. Keep provenance outside the indexed directory to avoid self-reference.

| Boundary | One coordinated supplied-mode change; preserve generated mode |
| --- | --- |
| Project → Analysis composition | Admit one shared Reference/source before composing each Analysis tail. Closed authored, normalized and Attempt records need a reviewed compatible shape. |
| Stage map/profile → planner → Snakemake | Conditionally omit 00a construction and its 00a→01 edge across semantic keys, owner tasks, expected Tasks, materialization and installed graph checks. Stage 01 receives an external input with no producer node. An Analysis requiring 00a must fail until separately supported. |
| Generated/supplied graph fixture | At the audited base: 12 owners/12 edges/57 artifact templates versus candidate 11/11/41, removing only 00a and its 15 members plus report. Keep 00b/00c and every other edge; counts are pinned expectations, not universal constants. |
| Immutable identity | Bind source mode, complete member fingerprint and identity-significant admitted provenance once through existing processing compatibility/Plan authority. Decide unused 00a resource/code inputs and evidence-route compatibility. Different bytes or material provenance create a distinct Run or refuse continuation. |
| Attempt/Task retention | Bind actual source/evidence paths and full record digest/trust proof at an approved boundary. Path-neutral Run identity does not relocate a verified Task; old dispatch inputs retain paths. A digest without retrievable evidence cannot readmit lost history. |
| Reports | The Reference projection affects report identity; decide physical-path sensitivity together with schemas. External input is not an output or construction report. Existing generated adapters may already accept absent 00a rows: prove that before changing them. |

Optional schema edits can change generated implementation identity even when old
Project input remains valid. Preserve historical read-only meaning and current
same-install resume limits; do not promise resume across installation changes.
No second identity object, provenance registry, Artifact Store or backend is needed.

## Admission and recovery checkpoints

| Checkpoint | Required future behavior and claim ceiling |
| --- | --- |
| Init preview | Read-only declaration and numeric-setting review; disclose index-byte verification pending. Generated mode acquires no mandatory new prompt. |
| Creation / validate / Doctor | Full present-byte and origin admission before `Project ready`; recheck before completion publication. Source visibility on the head does not qualify compute storage. |
| Direct Run/resume confirmation | Recheck the previewed content after approval **before** publishing new Run/successor Attempt authority, then at Task entry; executing the same preview object is not fresh admission. |
| Slurm head / compute | Head schema/submission review discloses verification pending; compute performs full source admission before Run creation. |
| Task execution/publication | Declare the external directory as input and compare its fresh full roster with the immutable admitted fingerprint, not only the prior per-Task snapshot. Never publish, copy, repair or clean the supplier directory. |
| Completed inspection / resume / reuse | Re-admit required index and historical evidence. Distinguish missing/changed provenance from missing/changed index; preserve locks/partials. Set lifetime and relocation explicitly. |

Per-sample Stage 01 and later inspection can repeatedly hash the whole index.
Measure representative planning, N-sample execution, resume and inspection before
accepting the strategy or optimizing it; preserve drift detection at each trust
boundary and state the mutation-during-read limitation.

## Focused protection and implementation gate

Retain independent expected digests/rows and cases for changed FASTA bases with
unchanged contig lengths, GTF changes, same-size rewrites/restored mtime, hidden or
extra member drift, swapped/linked/nested entries, hardlink aliases and changed
provenance with identical index bytes. Test untrusted/post hoc records, incomplete
builds, unsupported recipes and contradictory native metadata even when a newly
sealed inventory matches. Test preview-to-confirmation drift, source/evidence loss,
relocation and generated-mode literal roster/identity behavior. A supplied reporting
fixture omitting 00a rows proves reader acceptance only, not graph or Run authority.

Use existing STAR names/parsers, byte/directory helpers and Task boundaries;
deriving the planner's literal member count is a small candidate, not a demonstrated
full-feature reduction. Similar contig parsers accept different inputs, and shell
output checks versus Task input checks protect different boundaries. Keep those
independent protections. No new dependency, import wrapper or index cache has a
proven capability gap. The old 7–18-product-file estimate is provisional, not an
approved file roster or growth allowance.

Select provenance, public shape, storage, graph, identity and report policy first;
then approve one complete caller migration and quantified footprint. Implement one
admission path through every listed consumer, update owners/guides, and verify
public/installed/generated parity before exact-commit hosted checks. A selected
tiny real-STAR supplied-index journey is separate from mocks and from Slurm/site
qualification. No scientific or biological acceptance follows. Stop if historical
source identity, recovery, generated-mode parity or required approvals cannot be
preserved; do not merge a route that fabricates completion.
