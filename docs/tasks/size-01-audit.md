This working audit annex belongs to the [EMRYS polish campaign](polish-campaign.md#current-follow-up-scope). The [main findings matrix](backlog_matrix.md#maintainability-and-release) remains the sole authority for SIZE-01 status and acceptance. ## Scope and method

Inventory snapshot: 3a672fdf8e55b30efc63dea9aecc4a29d28a5f4d. This inventory covers every tracked, non-test text file at that commit, not just files changed on the integration branch. A file qualifies when it has more than 600 physical lines; a final line without a newline counts. The 38 qualifying files contain 56,985 lines: 15 coordinator Python files, 11 other Python files, two R files, four Markdown files, three dependency locks, one CI workflow, one JSON profile, and one stylesheet.

The tables separate observed responsibility from the next question. A proposed reduction requires a caller-complete review of behavior, protection, evidence, and ownership. No path-specific size exception has been approved. If a file is retained above the limit, record its exact path, reason, explicit user approval, and a retirement condition when the exception is temporary.

The audit reviewed implementation, contracts, callers, tests, and documentation. Its findings are source observations; product tests, hosted CI, Slurm, scientific analysis, and report visual review are separate evidence layers.

## Cross-owner discoveries

1. **Resource compatibility view.** [ResourcePlan](../../src/emrys/orchestration/run_coordinator/resource_policy.py#L213) presents one policy and one Attempt resolution through seven forwarding properties. Static source search found no direct production use of its declaration property; allocation is used inside policy_record. Replacing all production and test callers could remove roughly 25–27 product lines in a conceptual diff, still leaving the file near 630 lines and changing a published interface. An actual caller-complete diff and compatibility decision are needed before counting any saving; symbolic Run policy and numeric Attempt resolution remain distinct.

2. **Figure constants.** The Step 09 and Step 10 figure modules contain the same eight-color pair tuple and legend limit at [figures.py](../../src/emrys/reporting/paired_cmh_candidate_ranking_report/figures.py#L43) and [scientific_context_figures.py](../../src/emrys/reporting/paired_cmh_candidate_ranking_report/scientific_context_figures.py#L48). Step 10 already imports six private renderer helpers from Step 09. Reusing both constants through that import would remove 11 definition lines and add two imports, an estimated nine-line product reduction before an actual diff. The plotting branches have different zero-pair legend behavior, alpha, and bounded-note text; they do not have one shared rendering policy.

3. **Watch stream reads.** [refresh_snapshot](../../src/emrys/orchestration/run_coordinator/_inspection_presentation.py#L664) syncs retained full-history scheduler caches for workflow and identity projection, then [read_tail](../../src/emrys/orchestration/run_coordinator/_inspection_presentation.py#L371) opens the selected bounded tail. A selected scheduler stream has two independent observations, with overlapping byte reads on initial, appended, or replaced data; an unchanged full cache reads no appended bytes. The tail escapes controls that full-history sanitization strips, so reusing displayed full-cache text is not equivalent. A single admitted observation remains a hypothesis pending rotation, bounds, diagnostics, timing, and source-switching proof; no code reduction has been measured.

4. **CI measurement and selection.** The [inline Doctor measurement program](../../.github/workflows/ci.yml#L440) occupies about 191 workflow lines and is exercised by [extracted-driver tests](../../tests/test_ci_workflow.py#L602). Selected 130/100,000-pair conditions recur in evidence seeding, execution, uploads, and the final gate, while job admission has an earlier condition of its own. A new selector step cannot replace that job-level condition and may add machinery. Retain job identity, gate outcomes, and failed-run artifacts; no net workflow reduction is established.

5. **Profile key repetition.** In [local_cmh_v2.json](../../src/emrys/workflow/contracts/local_cmh_v2.json#L5), semantic_owner_keys and required_owner_keys currently equal the 12 owner_tasks machine keys in order. The [validator](../../src/emrys/contracts/orchestration/api.py#L355) enforces set equality, not order equality. The [selected-module writer](../../src/emrys/analyses/__init__.py#L159) also emits all three lists, while Task admission and Run projection consume them. Derivation needs every writer, reader, identity use, and retained-profile rule checked under existing schema/profile decisions; equal current values do not establish equal meaning.

6. **Operator and owner documentation.** The [Runbook's Init detail](../operations/RUNBOOK.md#create-a-project-for-your-own-data) overlaps the [coordinator contract's admission detail](../../src/emrys/orchestration/run_coordinator/CONTRACT.md#no-write-and-publication-boundaries). A precise owner link may shorten operator prose while retaining paste-ready actions and recovery. The [polish campaign's historical PR tables](polish-campaign.md#existing-capabilities-and-overlapping-work) are another compression candidate, subject to its [disposition and transfer rule](polish-campaign.md#campaign-disposition).

7. **Delegated verification record.** The [cluster backlog](cluster_verification_backlog.md#verified-scope-and-remaining-evidence) remains the acceptance and evidence owner for its CV cards. Its stated retirement condition requires exact evidence-bearing records and lasting decisions to reach durable homes first. A temporary size exception is a candidate; immediate deletion would risk losing active acceptance or retained evidence.

### _inspection_presentation.py

The [full-history trace pass](../../src/emrys/orchestration/run_coordinator/_inspection_presentation.py#L664) retains up to two scheduler stream caches, then the [selected tail](../../src/emrys/orchestration/run_coordinator/_inspection_presentation.py#L371) uses a temporary bounded cache. When the selection is a scheduler stream, the full pass and tail each admit it; the tail rereads up to 64 KiB even when the retained cache has no new bytes. The full pass keeps sanitized history for workflow and identity parsing, while tail display must escape ESC, BEL, CR, and TAB and retain at most 256 lines. Slicing sanitized full-cache text would change output. The current setdefault call also constructs a throwaway StreamCache and lock for each already-cached scheduler source on every refresh; eliminating those allocations may improve runtime state without reducing product lines. [Dashboard stream tests](../../tests/orchestration/run_coordinator/test_dashboard.py#L528) and [watch tail tests](../../tests/orchestration/run_coordinator/test_inspection_presentation.py#L589) protect distinct behavior. Next proof: compare raw-byte projection, path admission, rotation, timestamps, diagnostics, and selected-source switching before changing cache ownership. No net code reduction is established.
