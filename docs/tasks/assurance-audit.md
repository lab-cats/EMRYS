### A01-110 — Duplicate HTML attributes can hide active style and DOM identity

The rendered-report inspector receives an ordered list of attributes from Python's `HTMLParser`, then converts it to `dict`, keeping the last value of any repeated name (`src/emrys/reporting/_run_report/validation.py:210-216`). It stores that map for `<main>` and compares `data-report-view`, `data-run-id`, and other provenance fields with the expected identity (`:243-246,457-475`). It also passes only the mapped `style` value to its embedded-CSS check (`:285-292`). A standard-library probe with first `data-run-id="foreign"` and `style="background:url(https://example.invalid/a)"`, followed by second values `data-run-id="expected"` and `style="color:black"`, retained both pairs but exposed only the second values in the map. The [HTML Standard](https://html.spec.whatwg.org/multipage/parsing.html#attribute-name-state) specifies that a browser discards later duplicate attributes, leaving the first values in the DOM. The inspector's separate active-resource loop reads every original pair but does not inspect inline `style` there (`:293-314`; `src/emrys/reporting/_run_report/models.py:25-42`). The same bytes can therefore have a first-value browser style containing a non-embedded URL while the static CSS check sees only the benign second value, as well as a different DOM provenance identity. This is source composition plus a parser probe, not a completed report transaction or observed installed-template output.

The current provider-markup tests mutate active resources and event attributes but do not challenge duplicate provenance or style names (`tests/reporting/test_report.py:480-512`), and the installed template is not shown to generate duplicates. Required banner, one-main, per-pair event and URI checks, exact output-byte, receipt, and post-publication rechecks remain separate defenses (`src/emrys/reporting/_run_report/validation.py:293-314,370-475`; `src/emrys/reporting/_run_report/publication.py:154-180`). Reject duplicate HTML attributes before semantic checks, rather than trusting the last-value map. No browser network request was observed in this audit.
