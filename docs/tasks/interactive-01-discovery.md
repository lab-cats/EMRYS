## Proposed journey, not an approved transcript

1. The Quickstart owns installation before the CLI exists. The proposed guide
   begins on the head node after installation; settle that scope explicitly.
2. Show loaded settings and effective precedence. Choose new or exact existing
   Project. For first setup only, review one absent-file save and retain its
   effective values; decide outside-checkout and refusal/EOF behavior.
3. For new Projects, use existing Init questions and full review. The Viking
   example explicitly supplies its EV/PUM1 assignments, strand, comparison,
   region manifest, target and disclosed thresholds; none is inferred by site.
   Cover mixed strands, multiple conditions, background and missing mates.
4. Continue only from an admitted created/existing Project. Validate read-only;
   explain fresh input reads. Select current environment, explicit donor or
   Doctor-managed preparation as appropriate; discovery is not unconditional.
5. Diagnose the exact selected profile and approve only Doctor-owned work.
   Declined repair, blockers and incomplete qualification stop before Run.
6. Review the exact Analysis and direct plan or Slurm request once. Obtain the
   owner's execution/submission outcome; accepted submission is not a created,
   scientifically complete or reported Run.
7. Offer request-bound inspection, preserving the exact request across refresh
   and re-entry. If watch is declined, print exact inspection selectors. Later
   association, completion, stop and recovery retain their existing owners.

## Public outcome and evidence constraints

Preserve named-command outcomes: Setup preview and save can both return zero;
Init/runtime/Run previews and final refusals can return zero; required-answer EOF
can instead be an error. Doctor not-ready/blocked/declined results differ from
interrupted repair, wrong-node use and delegated compute success. Menu cancel
and a watch snapshot can return zero with no admitted Run. Public zero is never
a generic permission to continue the guide.

Prompts generally require stdin/stderr terminals; watch requires stdin/stdout
and a non-dumb terminal, while actions need all three. Approval questions printed
to redirected stdout must not leave a hidden prompt. Passing the exact request
avoids a separate ambiguous-target picker; it does not bypass fresh admission.

The initial private Init `Path | None` seam and roughly seven-net-line estimate
were unapproved source sketches, not a measured patch or growth allowance. Recheck
current callers before selecting owner-private outcomes. Reuse existing validation,
runtime plans and request identities; retain independent boundary checks and
avoid new schemas, saved scientific defaults or wizard checkpoints.

A selected implementation must cover no-write refusal/EOF at every approval,
source and installed entries, terminal/redirection cases, exact public exits,
input/profile drift, partial publication, duplicate submission and request-to-Run
reverification. Applicable hosted checks bind the implementation commit; fresh
novice Viking acceptance remains separate. Update the Quickstart to one composed
journey only after it works. Quantify product files/lines before seeking any needed
growth exception; test or evidence deletion cannot offset product growth.
