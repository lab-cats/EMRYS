# Just-in-time task cards

The backlog is coarse by design. When an actionable item is selected, create
exactly one `CARD-ID-short-title.md` file here after refreshing live Git state,
the item, direct owners and consumers, and applicable contracts.

The H1 is `# CARD-ID — Title`. Use these headings exactly once and in order:

1. `Outcome`
2. `Touches`
3. `Stop`
4. `Context`
5. `Deliverables`
6. `Acceptance evidence`
7. `Documentation updates`

`Outcome` states one observable result. `Touches` is the closed write scope.
`Stop` names semantic, authority, evidence, and scope-expansion conditions that
halt the package. The remaining sections contain only direct implementation
context and proportional proof. The backlog remains the owner of identity,
kind, technological blockers, intent, and durable boundaries.

A JIT card:

- cannot exist for a proposal or unknown backlog ID;
- cannot make a blocked item ready;
- grants no mutation, runtime, cluster, publication, or evidence-promotion
  authority beyond the user's explicit approval;
- is deleted when the execution package completes or ceases to be active; and
- is never a journal, historical archive, program roadmap, or second handoff.

The full predecessor card schema and wording remain available at commit
`755678ec28a6aa4e58149447704551312e365254`; reconcile useful archived detail
against current canonical owners rather than copying it mechanically.
