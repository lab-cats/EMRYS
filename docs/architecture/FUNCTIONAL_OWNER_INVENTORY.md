# Current functional-owner inventory

This implementation-backed roster assigns every current public script,
validator, and Make interface exactly once. Functional-owner slugs are
the stable public identities owned by
[`STAGE_MAP.md`](../../src/emrys/contracts/STAGE_MAP.md); this inventory owns
their current executable surfaces and direct protection, not identity or DAG
definitions.

The executable roster is protected by
[`test_public_cli_contracts.py`](../../tests/test_public_cli_contracts.py), and
public Make expansions by
[`make_target_expansions.json`](../../tests/fixtures/public_cli_contracts/make_target_expansions.json).
Files beginning with `_` and the explicitly listed orchestration helpers are
private library surfaces, not additional public entry points.

## Command audience classification

Every supported command has one primary audience even when the fixed workflow
also invokes it:

| Class | Command surfaces | Support boundary |
| --- | --- | --- |
| Researcher-facing | `emrys init project`, `init manifests`, `init synthetic`, `validate project`, `doctor`, `run`, `resume`, `report`, and `inspect run` | The normal `Project -> named Analysis -> immutable Run -> Results` journey. `init manifests` drafts strict inputs without inventing biology; `init project` validates and references those inputs while creating the Project-owned root without selecting execution/runtime policy. Validation, runtime discovery, and Doctor admit every named Analysis; Doctor and `run --analysis NAME` then select one readiness/execution context, with omission allowed only for a single-Analysis Project. `run` and Doctor derive the Project root and admitted runtime; Doctor reports Project, input, storage, runtime, and execution readiness without writing by default, while its explicit `--repair` action is an operator-authorized managed-runtime mutation. `run` and `resume` own direct or single-allocation Slurm placement; `report` independently plans, generates, or reuses the fixed downstream report projection. None exposes raw Snakemake or low-level reporting controls. |
| Operator-facing | `runtime discover`; `convert gtf-to-bed12`; `validate manifest`, `artifact-contracts`, and every numbered owner output; `reconcile reference-provenance`; `inspect runtime-availability`, `storage-inventory`, and `storage-qualification`; direct owner producers; and the manual runtime/data-check utilities | Runtime discovery dry-runs before publishing the single Project-owned runtime authority. The other routes provide explicit standalone production, validation, readiness, or diagnosis. None creates or adopts local-pilot Run state. Scheduled scientific execution belongs to grouped whole-Run control. |
| Workflow-owned | `validate all-pass` and the fixed workflow's `emrys.orchestration.local_pilot.task` module command | Stable semantic task boundaries invoked by the source-checkout workflow. Reporting no longer runs inside the workflow. |
| Internal | Private implementation modules plus repository development, test, documentation, and dependency-maintenance helpers unless this inventory explicitly assigns a public surface | No supported scientific or operator command is implied by importability, executable mode, or a module-local test harness. |

This classification does not weaken compatibility: a command remains supported
according to its owner even when it is not promoted into the researcher-facing
journey. Changing a command's class, hiding it, or adding a new route is a
public-surface decision requiring explicit approval.
