# Current functional-owner inventory

This implementation-backed roster assigns every current public script, SLURM
job, validator, and Make interface exactly once. Functional-owner slugs are
the stable public identities owned by
[`STAGE_MAP.md`](../../src/norad/contracts/STAGE_MAP.md); this inventory owns
their current executable surfaces and direct protection, not identity or DAG
definitions.

The executable roster is protected by
[`test_public_cli_contracts.py`](../../tests/test_public_cli_contracts.py), the
job roster by
[`test_slurm_wrapper_contracts.py`](../../tests/test_slurm_wrapper_contracts.py),
and public Make expansions by
[`make_target_expansions.json`](../../tests/fixtures/public_cli_contracts/make_target_expansions.json).
Files beginning with `_` and the explicitly listed orchestration helpers are
private library surfaces, not additional public entry points.

## Command audience classification

Every supported command has one primary audience even when the fixed workflow
also invokes it:

| Class | Command surfaces | Support boundary |
| --- | --- | --- |
| Researcher-facing | `norad init local-pilot`, `init synthetic-local-pilot`, `prepare local-pilot-runtime`, `validate local-pilot-request`, `doctor local-pilot`, `run`, `resume`, `inspect local-pilot-run`, and the lifecycle-generated `run-in-slurm.sh` | The normal first-run and recurring whole-run journey. These commands do not expose raw Snakemake controls or install dependencies. |
| Operator-facing | `norad build report`; `convert gtf-to-bed12`; `validate manifest`, `artifact-contracts`, and every numbered owner output; `reconcile reference-provenance`; `inspect runtime-availability`, `storage-inventory`, and `storage-qualification`; direct owner producers; owner-local `.slurm` entry points; and the manual runtime/data-check utilities | Explicit standalone production, validation, readiness, reporting, or diagnosis. Standalone owner work never creates or adopts local-pilot run state. |
| Workflow-owned | `norad build artifact-index`, `build run-summary`, and `validate all-pass`; the fixed workflow's `norad.orchestration.local_pilot.task` and `reporting_boundary` module commands | Stable transaction or task boundaries invoked by the source-checkout workflow. They are documented for bounded diagnosis/recovery, not as the normal researcher journey. |
| Internal | Private implementation modules plus repository development, test, documentation, and dependency-maintenance helpers unless this inventory explicitly assigns a public surface | No supported scientific or operator command is implied by importability, executable mode, or a module-local test harness. |

This classification does not weaken compatibility: a command remains supported
according to its owner even when it is not promoted into the researcher-facing
journey. Changing a command's class, hiding it, or adding a new route is a
public-surface decision requiring explicit approval.
